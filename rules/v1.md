# Ruleset 5-experimental

This file defines every scored rule: its budget, its thresholds and what it owns. `theme-report explain <rule-id>` prints the matching row. The ruleset version in reports and prompts is `5-experimental`.

WCAG contrast ratios use the standard formula. The OKLab thresholds, state thresholds and severity bands are this project's own heuristics. An A is not an accessibility certification. Any change to budgets, thresholds, ownership, models or applicability ships as a new ruleset version with updated golden tests.

Category totals: validity 20, readability 30, semantic 20, shell 20, wallpaper 10. A caution loses half the rule's budget; a failure loses all of it. An unassessed rule adds nothing to the assessed budget and loses nothing. It never counts as a pass.

Foundation and selected-menu text carry higher budgets because that text is always on screen. Tooltips carry less because they are secondary, not because a translucent default should pass. An unresolved surface is unassessed and makes the grade provisional. Text is never assumed to be large, because the runtime font size is unknown.

## Applicability, context, and ownership

All 22 rules apply to the supported profile. A missing input does not exempt a rule. A rule that depends on runtime behavior the analyzer cannot verify is unassessed and shown as "paused". If palette loading itself is unverified, every rule pauses (see `docs/supported-runtime.md`). A theme without its own `shell.toml` uses the runtime defaults, and that is not a defect. Broken core inputs keep their blocking caps. Unmeasured checks stay visible as limitations instead of blocking every grade.

Each deficit is charged once, to the rule that owns it:

- `validity.palette` owns syntax errors. `validity.roles` owns unresolved core colors; contrast checks that depend on them are unassessed, not charged again.
- `validity.backgrounds` owns corrupt media.
- Core readability owns each text deficit on an opaque or reference surface, including lock text over sampled wallpaper.
- Shell fill checks measure the color cue only. They do not score text contrast or claim full control accessibility.
- Wallpaper rules own any further loss under their sampled model. A deficit already charged under core readability stays in the wallpaper evidence without a second charge.

All images and sampled video frames share one budget per wallpaper rule, through the minimum measured contrast. If any expected media is incomplete, the whole media-dependent rule is unassessed. Identical media is decoded once by content hash, but every copy's bytes and role stay in the fingerprint. Video is valid media, not a theme defect. Missing codecs or tools, HDR or color-management requirements and resource limits produce limitations. Adding files never multiplies a rule's budget.

A scored text pair needs supported colors and one of: an opaque surface, complete sampled lock wallpaper, or the `application-gray17-v4` background scenario. That scenario grades translucent text, fills and borders over seventeen reference grays from black to white. It does not claim to measure live pixels or every possible RGB background. Solid role references resolve recursively with cycle detection. Popup-border gradients sample 17 points per adjacent pair of 2–8 color stops. RGB, RGBA and hex border stops keep their alpha, are multiplied by `border-alpha` with the same byte rounding as Omarchy, and are interpolated as premultiplied encoded-sRGB components. Unsupported formats are unassessed with a parser or geometry reason; translucency alone never withholds a measurement. There is no blanket ANSI readability or bright-color lightness rule. Lua syntax gets an unscored advisory, not a pass.

Semantic rules measure whether a role is visible, not color-only separation between labeled success and error controls. Terminal selection compares the selected and ordinary surfaces; selected-text readability is a separate rule. Fill checks grade the modeled color cue only. A weak cue is a caution, never a failure inferred from labels, icons or borders the analyzer cannot see.

## Score and grade

For assessed, unsuppressed budget A and deductions L: `score = 100*(A-L)/A`, overall and per category. Categories with nothing measured add neither budget nor loss. Grades: A ≥90, B ≥80, C ≥70, D ≥60, F below 60, using unrounded scores. The numeric score is diagnostic JSON data; the panel shows letters.

The overall state is provisional when an expected scored check is unassessed or suppressed. A partly measured category is `limited`, a category with nothing measured is `not-checked`, and one where no rule applies is `not-applicable`. With no assessed scored budget the report is `not-graded`, with no score or letter. Suppression keeps the evidence; it exists in the data model but is not a user setting. Zero-budget advisories never make a grade provisional.

A blocking validity failure caps the overall and validity grades at D (A, B or C become D; F stays F). Raw scores are unchanged. Core failures keep their losses even when downstream checks cannot run. There are no coverage gates or mandatory-check eligibility rules.

Calculations use f64. Display rounding never decides severity or grade. Golden tests allow a 1e-9 numeric tolerance; threshold comparisons do not. Non-finite values are unassessed. An A is not WCAG Level AA and not an accessibility guarantee.
